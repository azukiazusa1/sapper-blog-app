# 記事タイプ別の構成

記事の目的に合う型を選び、不要な節を機械的に追加しない。詳しい文体と統計は `contents/BLOG_WRITING_GUIDE.md` を参照する。

## 新しい API・機能の紹介

1. 対応状況と実験的機能である場合の警告
2. 現在の課題または従来のコード
3. 仕様策定の背景、検討された代替案、現在の形になった理由
4. API の定義と最小例
5. 仕様上の細かな挙動
6. 実際に動かすサンプル
7. 実行結果と観測
8. 制約、互換性、フォールバック
9. まとめ・参考

サンプル実装と実環境での検証を必須とする。

## ハンズオン・実装チュートリアル

1. 技術の概要と完成形
2. 必要なら構成図
3. 前提条件、プロジェクト作成、インストール
4. ファイル単位の段階的な実装
5. 起動・操作コマンド
6. 期待するログや画面
7. 応用機能または運用上の注意
8. まとめ・参考

読者が新しい環境で再現できるよう、import、依存関係、環境変数、起動手順を省略しない。

## 調査・比較記事

1. 調査対象となる具体的な問題
2. 調査範囲、比較軸、検証環境
3. 判断に必要な標準・基礎概念
4. 対象ごとの観察
5. 共通点と相違点
6. 調査結果を反映した実装または判断基準
7. 実機での検証結果
8. まとめ・参考

事実と評価軸を分離する。比較対象に同じ条件を適用する。

## 意見・経験記事

1. 現在の立場や経験の変化
2. テーマごとの実践と理由
3. 利点だけでなく限界や反論
4. 適用できる範囲と一般化できない範囲
5. 今後変わり得る点
6. まとめ

一人称を使用してよい。個人の経験を一般的な事実として断定せず、外部の事実を述べる箇所には根拠を付ける。
