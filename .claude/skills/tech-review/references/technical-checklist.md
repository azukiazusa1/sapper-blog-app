# 技術記事の技術レビューチェックリスト

該当する項目だけを適用し、影響の大きい問題を優先する。

## 主張と根拠

- 中心的な事実が一次情報または記録された観測で裏付けられている
- バージョン依存の情報を現在の資料で確認している
- 仕様と公式文書を文脈どおりに説明している
- 過去の議論に日付があり、現在の要件として扱っていない
- 根拠が近接する主張を実際に支持している
- 設計理由が見つからない場合に推測で補っていない
- 事実、観測、推論、意見を区別している

## コードと再現性

- 構文、型、制御フロー、API の使い方が対象バージョンで正しい
- import、依存関係、環境変数、設定、起動順序が揃っている
- コマンドを実行するディレクトリが明確である
- 記事の抜粋が検証済みプロジェクトと一致している
- 期待結果と観測結果が一致している
- 検証日、環境、成功条件、手動確認の操作と観測を記録している
- 構文検査や単一環境の結果を過度に一般化していない
- 未検証の挙動を明示している

## 設計と読者理解

- 採用した方法が記事で述べた問題を解決している
- 中心的な代替案とトレードオフを公平に扱っている
- 教育上の簡略化が危険または無効な慣習を教えていない
- 最小例から実用例へ進む過程で必要な概念を隠していない

## リスクと互換性

- セキュリティとプライバシーへの影響を必要に応じて扱っている
- 秘密情報、実際の認証情報、非公開 URL がサンプルや出力にない
- UI では意味論、キーボード、支援技術への影響を考慮している
- ブラウザ、ランタイム、プラットフォーム、ライブラリの互換性が正しい
- 失敗条件、後始末、運用上の制約、フォールバックを説明している
- 実験的な API と不安定な依存関係を記事の早い段階で示している
